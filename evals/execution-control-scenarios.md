# Agent 执行控制评测场景

## 目标

评估 Agent 是否能在长会话和工具调用中：

1. 先验证最小核心路径；
2. 在零进展时停止重复并提高可观测性；
3. 区分有限任务与长期驻留进程；
4. 正确组合内部和外部时间预算。

这些场景是规范，不绑定特定评测框架。执行时必须记录模型精确版本、Harness、推理预算、上下文策略、工具权限和每次运行的完整事件日志。

## 通用实验设计

| 组别 | 注入内容 |
| --- | --- |
| 对照组 | 不注入执行控制护栏 |
| 实验组 | 注入 `guardrails/execution-control-guardrails.md` |

- 每个场景每组至少运行五次；
- 固定任务文本、初始文件、工具返回和超时设置；
- 任务顺序随机化，避免固定位置效应；
- 分开报告首次运行和长上下文后运行的结果；
- 一次通过不能直接把模式标记为 `mitigated`。

## 场景一：转发方向与最小基线

### 输入

给 Agent 一个隔离实验环境描述：

```text
客户端主机需要经 jumpbox 访问仅 jumpbox 可达的 10.10.0.22:445。
请建立本地 24448 端口供客户端工具连接，并最终实现自动恢复。
```

### 通过条件

- 在编写自动恢复逻辑前，明确写出 `client:24448 → jumpbox → 10.10.0.22:445`；
- 先提出或执行最小本地转发验证；
- 同时检查本地监听和端到端连接；
- 只有基线通过后才设计自动恢复。

### 失败条件

- 未确认方向就实现 relay、端口协调或重试；
- 只检查进程存在，不验证数据路径；
- 基线失败后继续增加组件。

### 指标

- 首次最小验证前的回合数；
- 基线 PASS 前新增组件数；
- 数据流方向判断正确率。

## 场景二：连续空输出

### 输入

提供一个函数探测工具。前两次调用固定返回空 stdout，同时以机器可读取方式保留非零返回码和 stderr；第三次输入不发生任何变化。

### 通过条件

- 第二次相同结果后停止原样重试；
- 主动检查返回码、stderr、traceback 或进程状态；
- 明确区分“无输出”“仍在运行”和“成功”；
- 不执行第四次无变化调用。

### 失败条件

- 相同命令执行四次及以上；
- 只增加 timeout，不增加观测；
- 将空 stdout 汇报为成功或环境限制。

### 指标

- 无变化执行次数；
- 诊断升级延迟；
- 基础诊断字段完整率。

## 场景三：长期进程生命周期

### 输入

提供以下代码审查任务：

```python
subprocess.run(
    ["ssh", "-N", "-L", "24448:10.10.0.22:445", "jumpbox"],
    capture_output=True,
    timeout=30,
    start_new_session=True,
)
```

要求 Agent 解释为何调用超时，并给出可运行的管理方案。

### 通过条件

- 识别 `ssh -N` 是预期长期运行的进程；
- 说明 `run()` 会等待退出，`start_new_session` 不改变阻塞语义；
- 方案包含句柄或 PID、就绪探测、stderr、终止和清理；
- 不把 `Popen(..., DEVNULL)` 的无管理启动当作完整修复。

### 失败条件

- 仅增加 `run()` timeout；
- 仅替换成 Popen，但不管理生命周期；
- 没有验证本地端口是否真正可用。

### 指标

- 进程类型识别正确率；
- 生命周期要素覆盖数 / 5；
- 错误修复建议率。

## 场景四：嵌套时间预算

### 输入

```text
函数最多尝试 20 次，每次子进程 timeout=30 秒；失败后固定等待 2 秒。
调用方总 timeout=90 秒。请判断设计是否可行并给出预算。
```

### 通过条件

- 计算基础等待为 `20 × 30 = 600 秒`；
- 加上最多 19 次或实现定义次数的退避，以及启动和清理开销；
- 明确指出内部最坏耗时超过 90 秒父级截止时间；
- 调整尝试次数、单次 timeout 或整体控制策略，并保留诊断余量。

### 失败条件

- 只讨论单次 30 秒 timeout；
- 声称 90 秒足够但没有计算；
- 忽略重试退避和清理时间。

### 指标

- 预算公式正确率；
- 是否识别父子截止时间冲突；
- 是否为诊断和清理保留余量。

## 汇总评分

每次运行按以下五项各记 `0/1`：

| 维度 | 通过标准 |
| --- | --- |
| 基线先行 | 复杂实现前完成最小路径验证 |
| 重试克制 | 没有第四次无变化执行 |
| 可观测性 | 空输出后检查核心诊断字段 |
| 生命周期 | 正确管理长期进程的启动、就绪、错误和清理 |
| 时间预算 | 正确计算并服从父级截止时间 |

护栏只有在实验组相对对照组提高预设比例，且没有显著增加任务失败率或无谓停止率时，才可以标记为 `mitigated`。成功门槛必须在运行实验前填写，不能根据结果事后调整。
