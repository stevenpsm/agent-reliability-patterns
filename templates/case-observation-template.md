未知信息写“未记录”，不要猜测。删除密钥、客户数据、真实攻击目标和私有代码。

## 用户目标与成功判据

描述用户真正要完成的结果，以及可以外部验证的完成条件。

## 初始状态

记录与案例有关的文件、配置、进程、网络拓扑和既有结论。

## 事件时间线

按发生顺序记录：

1. Agent 做了什么；
2. 工具实际返回什么；
3. 当时采用了什么假设；
4. 哪个后续证据推翻或支持该假设。

把直接观察与解释分开。无法提供原始证据时说明原因。

## 因果链

```text
起始条件
  → 决策或错误
  → 可观测结果
  → 后续决策
  → 用户影响
```

说明哪些事件共享同一个根因，避免把相关调用误算成独立复现。

列出本案例可能支持、扩展或反驳的既有模式。技术 API 或具体命令通常是实例，不自动等同于通用模式。

记录错误对正确性、时间、成本、安全和用户判断造成的影响，以及最终如何恢复。
